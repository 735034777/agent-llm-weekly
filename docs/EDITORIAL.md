# 编辑准则

## 定位与篇幅

面向希望持续了解 AI 研究、产业与实用工具的中文读者。固定三栏：论文与研究、新闻动态、开源项目。开头从正文挑三条导读；目标 12—16 条、10—15 分钟，不为凑数牺牲事实质量。通常研究 3—4、新闻 5—7、项目 4—5；按信息价值调整，数量不是硬校验门槛。

## 论文与研究

聚焦 LLM、Agent、推理、训练、记忆、工具使用、多模态与评测。优先近期顶刊顶会及重要实验室的一手材料，包括 NeurIPS、ICML、ICLR、ACL、EMNLP，Nature 系列、TMLR、JMLR，以及 OpenAI、Anthropic、Google DeepMind／Research、Meta、Microsoft、NVIDIA、DeepSeek、Qwen。出版社声望是线索，实际贡献与证据决定入选。

通常回看新闻周结束前 30 天；会议集中发布、版本正式发表时可回看至 60 天。标注具体 venue、正式发表／录用状态、日期与证据链接；区分主会、Findings、Workshop。OpenReview 投稿页不等于录用。预印本、技术报告、研究博客使用各自标签，不统称顶会论文。

每期选一篇略深入：问题是什么、做法有什么变化、证据支持到哪里；其余用短介绍交代值得读的部分。重要数字需给出模型、任务、基线及条件，无法核实就省略。作者报告不等于独立验证，只有摘要或索引可读时不声称读完全文。期刊版与早期预印本日期分别说明。

## 新闻动态

覆盖全 AI：产品、模型、价格与额度、融资与商业、芯片与数据中心、机器人、政策、就业、教育、社会争议，以及公开人物动态、趣事和可靠报道中的八卦。选择有信息量或讨论价值的事件，不限制为技术发布，也不为了固定类别硬凑。

首先找官方公告、当事人公开原帖和可靠媒体报道，再用社区、聚合站和中文媒体发现遗漏。新闻日期必须在对应周内；有明确时间戳时转换到北京时间，无明确时区则保留原来源日期并记录口径，临界日期无法判断就不作确定断言。区分发生、报道、宣布、上线、获批与计划。

Tibo 指 Thibault Sottiaux 的 @thsottiaux，固定关注其 Codex 公开动态。重置消息必须核对原帖、时间、适用对象与完成状态；banked reset、预告、社区预测和个人额度不可混用。原帖不可读时社区归档只能辅助定位，不以其推定到账，也不强行每期安排 Tibo。

人物负面消息与私生活指控必须有可靠公开报道或当事人证实；单个匿名账号和未经核实的截图不足以入刊。人物观点归属本人，编辑判断写清是判断，不给不存在的事件制造新闻。

新闻采用标题、事实摘要、必要背景和直接来源；不强制套“为什么值得看／局限”标签，不把厂商宣传写成已经证实的结果。

## 开源项目

参考 HelloGitHub 的 Skills 与人工智能栏目，以及其公开审核标准。范围扩展到全 AI：图像与设计、语音与音乐、3D、机器人、自动化、数据与模型工具、Agent 和 Skills。综合用途、特色、文档、上手入口、许可、维护和用户讨论选稿；同等价值时成熟项目更容易推荐，但不设 star 最低值或比例。

每期尽量覆盖不同用途，不反复罗列同一批大框架。项目可以因本周实质更新入选，也可作为本期发现：前者核实版本与发布日期，后者明确资料查询日期，不声称新发布。旧项目再次出现须有新信息；合集用于发现，不能将合集 star 算到子项目。

回原仓库读 README、示例、快速开始、许可证、近期提交和 Issues／PR。区分代码、权重、数据与素材许可，区分开源、开放权重、公开源码与自定义许可。star 必须附查询日期，历史期刊快照不随以后查询改写。

项目介绍先讲能做什么、适合谁，再给可实际使用的入口与必要环境。没有执行就不声称亲测，不运行来历不明的安装脚本以凑测试记录。只参考 HelloGitHub 的选取与组织方式，独立写文案；图片或演示须核对授权和实际价值。

## 配图

每期通常选 4—7 张能帮助理解内容的配图，不逐条硬配。优先官方新闻插图、研究方法图、项目界面或演示；不以 logo、广告和无关装饰图充数。先查看图片实际内容，再核对它与对应条目及版本的关系；作者提供的演示不可写成本刊实测。

直接使用原作者公开的图片链接，附简短中文图注、替代文本、作者／机构和原始来源。项目图片尽量固定到所引用提交，控制展示宽度并允许点击查看原图；优先清晰、体积适中的静态图，动图有实际信息价值且加载合适时再使用。核对原文中的许可与署名要求，保留水印；有单独授权要求时换用其他合适材料，不借用 HelloGitHub 的二次加工图片。

发布前检查链接返回真实图片，并检查 GitHub 正文与 Release 的显示。配图访问失败时可换原站有效地址，无法解决就保留图源链接，不用错误图片代替。

## 核查、表达与更正

- 每条附直接来源。技术内容用论文或作者／官方材料；新闻可用可靠媒体，并说明转引与未能核实的范围。
- 同一成果的论文、博客、代码合并，避免跨栏重复；同一事件后续报道须确有新增事实。
- 简洁准确，少用空泛评价，不使用“炸裂”“吊打”等宣传词。必要限制放在对应语境，正文不堆核查表。
- `source-reviewed` 表示完成注明范围的资料核对，`source-partial` 表示只读到摘要、索引或部分材料，`reproduced` 必须附真实条件和结果。等级不代表事实百分之百可靠。
- 信息源检查状态分别为 reviewed、partial、unavailable、not_checked；完成检查仅限注明范围。无法访问不能写成“没有新内容”。
- 详细证据放在 `evidence/NNN.md`，正文留链接。公开内容不含本机路径、凭证、私人材料或完整复制的第三方文章。
- 实质改动先修正 JSON、追加更正说明，再生成派生文件并同步 Release；保留 Git 历史，不移动已发布标签。

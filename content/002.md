### 1. Contrastive Discovery：实验否定了一个猜想，接下来支持哪个解释？

`会议论文 · NeurIPS 2026 · 已录用 · 所读预印本 v1 日期 2026-11-10` · 科学发现 / Agent / NeurIPS

科研 Agent 提出一个猜想、跑实验、发现它不成立，常常就停在“否定”这一步。Contrastive Discovery 把一次探索的单位改成一个问题及一组互斥、尽可能覆盖所有情况的解释，让同一份证据同时比较多个答案。例如，某因素与结果的关系可能是正相关、负相关或无关联；排除正相关之后，仍要判断另外两种情况。模型据此调整对各解释的信念分配，并用变化幅度引导后续搜索。

作者在六个领域的表格数据上，以 GPT-4o 为基础 Agent、每次运行 200 次证据生成作为比较条件，报告相对逐个假设的 surprisal 基线，多解决了 67% 的问题。值得读的是如何利用已有实验去区分竞争解释，而不是只奖励一个猜想被推翻。

“解决”依赖另一 LLM 给出的信念分配及阈值；候选解释也可能遗漏。这里得到的是观察数据上的统计结论，不等于因果发现或真实实验室突破。前四个数据集各运行三次，两个成本最高的数据集各一次；未由本刊独立复现。

[论文与录用声明](https://arxiv.org/abs/2611.14514) · [正文](https://arxiv.org/html/2611.14514v1) · [NeurIPS 官方收录目录](https://nips.cc/Downloads/2026)

### 2. AIDE：把科学数据整理交给多 Agent 流程

`期刊论文 · Nature Communications · Article in Press · 已发表 · 期刊在线发表日期 2026-11-04` · 数据整理 / 科学大模型 / Nature Communications

AIDE 把数据收集、筛选和整理串成一条流程，将自然语言的数据需求转换为可供科学 AI 使用的数据集。论文摘要报告，在生物医学与化学的 14 项任务中，用这条流程整理的数据训练或构建模型，表现达到或超过人工整理数据的对照。关注点是训练之前的数据工作，而非让 Agent 直接代替科学家下结论。

对于准备领域微调或检索数据的人，这篇研究把容易被忽略的收集、质量筛选、格式整理拆成了可以研究和评估的环节。

目前为已接受论文的提前在线版本，尚可能编辑。本文仅依据摘要及有限正文介绍；未核完各任务基线、成本和泄漏控制，不能把摘要结论外推为所有科学领域都适用。

[出版方与摘要](https://www.nature.com/articles/s41467-026-78887-x) · [出版方论文 PDF](https://www.nature.com/articles/s41467-026-78887-x_reference.pdf)

### 3. Google 的 sleep framework：把短期信息逐步写入模型参数

`研究博客 · Google Research · 研究博客发布日期 2026-10-27` · 持续学习 / 参数记忆 / Google Research

Google Research 介绍一种交替运行的学习流程：活跃阶段接收信息，离线“睡眠”阶段再做知识巩固。它在预先设计的架构内启用低秩专家和 MoE 记忆模块，将短期信息蒸馏进长期参数；另用生成、筛选的练习样本继续训练。这里的“睡眠”是离线训练步骤，模型代码和训练规则仍由人设定。

<p align="center"><a href="https://storage.googleapis.com/gweb-research2023-media/images/LLMSleep1_Framework.width-1250.png"><img src="https://storage.googleapis.com/gweb-research2023-media/images/LLMSleep1_Framework.width-1250.png" alt="Sleep framework 从活跃阶段的短期记忆进入知识巩固和 dreaming，再形成参数记忆的流程图。" width="800"></a></p>

*短期记忆在离线阶段经过巩固与练习，进入长期参数；图为作者的框架示意。 · 图源：[Google Research](https://research.google/blog/the-sleep-framework-a-new-way-for-llms-to-retain-knowledge-in-continual-learning/)*

适合关注持续学习的人阅读：它尝试在运行后更新模型的参数记忆，并研究如何减少学新知识时对旧能力的干扰。

这是研究方案，仍需离线计算、参数容量与训练过程；不能理解成任意已部署模型暂停片刻就能永久学习，也不能由文章示例推断所有任务都消除了遗忘。

[官方研究博客](https://research.google/blog/the-sleep-framework-a-new-way-for-llms-to-retain-knowledge-in-continual-learning/)

### 9. Impeccable：给编程 Agent 一套可执行的设计语言

`本期发现／资料快照 2026-11-16` · Skill / 界面设计

⭐ 110,757（2026-11-16 快照） · Apache-2.0；图片与示例中的第三方素材仍需遵循各自权利。

不只说“把页面做漂亮一点”，还可以用 polish、critique、audit 等明确动作，让 Agent 调整设计、评审可用性并检查常见界面问题。Impeccable 把这些操作做成设计技能，也提供源文件或页面检测器，适合已经在用 AI 写前端、希望进一步打磨视觉与交互的人。

npx 安装入口需要 Node；技能另有引擎运行条件。特别留意 live mode 的 Apply：README 提到无人轮询时会回退到关闭审批和沙箱的 CLI 调用，可配置为 chat 或 off。采用此功能前应读清执行权限。

### 10. ComfyUI：用节点把图像、视频和音频流程连起来

`本期发现／资料快照 2026-11-16` · 图像视频 / 创作工具

⭐ 147,033（2026-11-16 快照） · 核心代码 GPL-3.0；模型、第三方节点和云服务分别采用各自条款。

ComfyUI 把模型加载、提示词、采样、解码和保存做成可连接的节点，能保存和重复使用完整工作流。除了图像，也可组合视频、音频与 3D 相关模型；适合想控制生成过程、比较参数或接入创作管线的用户。比起一次性的提示框，它的学习成本更高，但过程更容易检查和复用。

具体显存和内存取决于模型与工作流，不能只看应用本身。自定义节点及模型需单独检查；Partner/API 节点可能依赖付费云服务，不能一概视为完全本地。

### 11. YuE2：先写可编辑的乐谱，再生成整首歌

`本期发现／资料快照 2026-11-16` · 音乐 / 开放权重

⭐ 13,516（2026-11-16 快照） · 代码、skill 与文档 Apache-2.0；权重为 CC BY-NC 4.0 加创作者额外许可，README 允许个人创作者变现输出，公司商业使用需另洽许可。不能把权重概括为无限制商用。

输入歌词和风格，YuE2 先产生旋律与和弦计划，再生成带人声和伴奏的歌曲。中间的 ABC 乐谱可以检查和修改，随后重新生成音频，也提供音乐 Agent skill。它适合希望干预作曲过程的人；编辑会产生新的完整录音，并不保证只改某一段而让其余波形保持不变。

**上手：** 先到官方项目页听示例。准备本地运行时，按照 Quick start 安装 Python 包并运行 examples/generate.py，输出会保留音频、乐谱及生成设置。

官方常规路径为 Linux、Python 3.12、支持 BF16 且有 24 GB 显存的 NVIDIA GPU；首次使用需下载模型。其他硬件与低显存路径须查看实验性支持范围。

[GitHub](https://github.com/multimodal-art-projection/YuE) · [文档快照](https://github.com/multimodal-art-projection/YuE/blob/1116bea76032bee5668e5f097294d082fa0b84f0/README.md) · [官方演示](https://map-yue2.github.io/)
